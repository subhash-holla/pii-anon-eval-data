Determinism note (pyarrow metadata caveat)

Byte-identical Parquet is not a stable contract: pq.ParquetWriter stamps the running pyarrow library version (and created_by) into the file footer's key/value metadata, so two runs differ in raw bytes even with identical logical content. Test #5 therefore asserts determinism over the logical table — table_a.schema.equals(table_b.schema) and table_a.equals(table_b) (schema + column data) — rather than raw bytes. Inputs to that determinism are themselves deterministic: column order is fixed (record fields in record order, then the ordered REGIMES reg_* columns appended last), and nested blocks are JSON-encoded with sort_keys=True, ensure_ascii=False so dict-key ordering can't perturb the encoded string. No clock/RNG is touched (AX-002-adjacent). This matches §6 test #5's explicit "compare the table contents not raw bytes".
