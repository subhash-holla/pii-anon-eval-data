8b. Implementation spec (authoritative)

Pure-stdlib (hashlib allowed — deterministic). Frozen results. No RNG/clock.

class AttackerCapability(str, Enum):
    ARTIFACT_ONLY          = "artifact_only"            # sees pseudonymized output only (Art 4(5) baseline)
    ARTIFACT_PLUS_AUX      = "artifact_plus_auxiliary"  # + web-like auxiliary
    KNOWN_PLAINTEXT_SUBSET = "known_plaintext_subset"   # knows some (real→pseudo) pairs
    CROSS_EPOCH_LINKAGE    = "cross_epoch_linkage"      # artifacts from 2 key epochs
    HOLDS_KEY              = "holds_key"                 # authorized reversal (legitimate holder)

@dataclass(frozen=True)
class ThreatModel:
    capabilities: tuple[AttackerCapability, ...]   # sorted, frozen
    model_id: str                                  # version-pinned, e.g. "pseudo-threat-v1"

@runtime_checkable
class Pseudonymizer(Protocol):
    pseudonymizer_id: str
    def pseudonymize(self, value: str, entity_type: str, *, context_key: str) -> str: ...
    def reverse(self, pseudonym: str, entity_type: str, *, secret: object) -> str | None: ...
    # reverse returns None when not authorized/possible; `secret` is the held key/state

@dataclass(frozen=True)
class ReferentialIntegrityResult: join_consistent: bool; n_joins: int; broken_joins: int
@dataclass(frozen=True)
class KeyRotationResult: post_rotation_authorized_reversal_succeeds: bool; cross_epoch_unauthorized_linkage_fails: bool
@dataclass(frozen=True)
class KeyStateSeparationResult:
    rejoinable_from_artifact_alone: bool
    note: str   # MUST cite EDPB Art 4(5); non-empty (validate in __post_init__)

@dataclass(frozen=True)
class PseudonymizationReport:
    threat_model: ThreatModel
    unauthorized_reversal: Interval        # wilson_interval(reversed_without_secret, n_pseudonyms)
    authorized_reversal: Interval          # wilson_interval(reversed_with_secret, n_pseudonyms)
    intended_linkage_collisions: int       # same real → same pseudonym (FEATURE) — SEPARATE
    unintended_crypto_collisions: int      # distinct reals → same pseudonym (FAULT) — SEPARATE
    crypto_collision_ci: Interval          # wilson_interval(crypto_collisions, n_distinct_inputs)
    referential_integrity: ReferentialIntegrityResult
    key_rotation: KeyRotationResult
    key_state_separation: KeyStateSeparationResult
    pseudonymizer_id: str
    # DELIBERATELY no total_collisions / combined / deid / overall / utility / residual_risk field.
    def as_dict(self) -> dict: ...

def score_pseudonymization(pseudonymizer: Pseudonymizer, records, threat_model, *,
                           secret, rotated_pseudonymizer=None, confidence: float = 0.95) -> PseudonymizationReport: ...

Check semantics (each a pure function; integer (k,n) → Wilson):

  • Unauthorized reversal: under ARTIFACT_ONLY/ARTIFACT_PLUS_AUX, attempt recovery WITHOUT the secret (dictionary/frequency attack over the candidate plaintext space); rate = recovered / n_pseudonyms.
  • Authorized reversal: under HOLDS_KEY, reverse(p, secret=key) success / n_pseudonyms.
  • Collision separation: group inputs by real value. intended_linkage_collisions = pseudonyms shared by inputs that are the SAME real value (correct). unintended_crypto_collisions = pseudonyms shared by DIFFERENT real values (fault). Report as TWO integers — never a sum.
  • Referential integrity: same real entity across records → same pseudonym (join key stable).
  • Key rotation: epoch A vs B; new key still authorizes reversal; an attacker with both epochs' artifacts cannot link the same entity across epochs.
  • Key/state separation (EDPB Art 4(5)): can records be re-joined from the artifact ALONE, no external secret? For bare-md5 (deterministic function of input, no secret) → True (fails separation — the correct, important finding). For salted+keyed → False. Note cites Art 4(5).

The bare-md5 example fails Art 4(5) — that is a correct finding to EXPRESS, not a bug to hide. The real scripts/enrich_context_preservation.py::PseudonymGenerator is exactly this shape; cite it in a comment as the real-world example the Protocol admits.

How the bare-md5 EDPB Art 4(5) finding is EXPRESSED (not hidden)

_BareMd5Pseudonymizer (no salt, no secret — the shape of the real scripts/enrich_context_preservation.py::PseudonymGenerator) produces a pseudonym that is a pure deterministic function of the input. _keyless_rejoinable(...) re-derives the keyless public digests (md5/sha256 + common truncations) of the closed-world candidate plaintexts and matches them against the artifact tokens; a hit ⇒ rejoinable_from_artifact_alone = True. The scorer then emits a non-empty KeyStateSeparationResult.note citing EDPB / GDPR Art. 4(5) stating the artifact is self-rejoinable and therefore does NOT satisfy the "additional information held separately" safeguard — and names the real PseudonymGenerator as the in-repo example. This is surfaced as the report's verdict, never suppressed.

Deviations / notes for reviewers

  1. reidentification.py:69 mypy type-arg (PRE-EXISTING, OUT OF SCOPE): under --follow-imports=silent mypy follows the sibling import and reports its dict missing type-params. It originates in foundation commit 75e9eed (and was already present before S3-07), and reidentification.py is NOT in this story's §8 owned files. Per scope discipline I did not edit it. The new file itself is mypy-strict clean. A one-line follow-up (dict → dict[str, object] at that line, matching :105) is suggested as a separate chore, not folded into S3-07.
  2. crypto_collision_ci denominator semantics: n = number of distinct real input values; k = distinct reals caught in an unintended (different-real) collision. So the CI reads "fraction of distinct inputs involved in a crypto collision," keeping (k,n) integer for Wilson (reidx-02 honored).
  3. Unauthorized-reversal / rejoinability attack is closed-world over the candidate plaintext space (the artifact's own distinct real values). This is the principled, signature-compatible realization of the §8b "dictionary/frequency attack over the candidate plaintext space" — it needs only the artifact + public hashes (no secret), which is exactly what makes a keyless scheme fail and a keyed scheme pass.
  4. _held_secret_of (rotated epoch): the key-rotation check reverses epoch-B tokens using epoch B's own held secret when the instance exposes one (best-effort getattr), else the passed secret. This keeps the "new key still authorizes reversal" probe honest for a rotated instance keyed differently from the primary, without widening the Pseudonymizer Protocol surface.
