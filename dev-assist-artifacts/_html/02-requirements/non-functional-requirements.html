Non-Functional Requirements (Quality Attributes)

Stage 2 · R1+R4 (folded) → R8/R9/R10 · 2026-05-28 · provisional_status: AGENT_SIMULATED Vocabulary: NFR = Quality Attribute. Each has a quantified threshold + measurement method. R10 threshold-validation outcomes recorded in _threshold-validation/.

Statistical rigor (the "credible benchmark vs big dataset" dimension)

  • NFR-001 — Per-slice statistical power (marginal + committed crossed cells). Threshold: every published score on a committed evaluation cell — each main-effect marginal (per language, entity-type, domain, difficulty, adversarial-type) AND every cell of the committed 2-way lattice (see 03-design/sampling-design.md) — has positives ≥ its risk-tiered target: ≥1,522 (recall≈0.99 ±0.5pp) for credential/financial-critical classes, ≥753 (≈0.98 ±1pp) standard, ≥200 (≈0.95 ±~3pp) long-tail — OR is labeled exploratory/low-power and excluded from headline claims. Measure: per-cell positive count vs tiered bar over the frozen eval_lattice.json; CI gate in validate.py --lattice. (AX-003; R10-validated; operationalized by NFR-018)
  • NFR-002 — CI on every metric. Threshold: 100% of published metrics carry n + a CI with the method named (Wilson/Clopper-Pearson); zero bare point estimates. Measure: report linter. (AX-003)
  • NFR-003 — Per-language (and language×type) power transparency. Threshold: a per-language positive-count table AND a per-(language×entity-type) power matrix are published; no aggregate "60-language" or "type-across-languages" performance claim without them; any language, type, or language×type cell below its tier target is labeled low-power. Measure: presence + per-cell count check, emitted by the DC-09 power-table reporter. (N7; extended to crossed cells per NFR-018)
  • NFR-018 — Committed-lattice per-cell power (hard gate). Threshold: every cell in the frozen committed evaluation lattice (src/pii_anon_datasets/data/eval_lattice.json — main effects + the 3 named 2-way interactions: language×entity-type, domain×track {evaluation-family AND adversarial-track}, adversarial-type×entity-type) meets its risk-tiered positive target (≥1,522 / ≥753 / ≥200, each derived from NIST proportion sizing n=⌈z²·p(1−p)/d²⌉ — never hand-typed); non-committed slices may ride the low-power enrichment flag (NFR-001) but committed cells MUST pass. Measure: validate.py --lattice audits positives per committed cell in one streaming pass and exits non-zero on any shortfall (CI-blocking); the spec round-trips against its deterministic generator (anti-drift) and asserts target_n == required_n(p_ref, half_width). R10 (ACCEPTED-WITH-CAVEATS, 10-persona, 2026-05-29): tier numbers locked; this is a corpus-power floor (count-based, non-flaky) DISTINCT from the FR-002 detector-regression gate (paired McNemar); the recall tiers scope to the detection track — anonymization/pseudonymization/RRS cells (DC-06/07/08) carry a separate re-id-operating-point power ladder (seam); the committed 2-way set is a curated D-optimal fraction, not Cartesian; every published per-cell metric carries a non-strippable synthetic-provenance/external-validity caveat (cf. FR-009, FR-027). (AX-003 at crossed-cell granularity; closes M2/M3; see _threshold-validation/findings-nfr-018-2026-05-29.md)

Reproducibility / integrity

  • NFR-004 — Deterministic, provenanced generation. Threshold: re-running a seeded generator yields a byte-identical record set (deterministic path) OR an LLM path records model+prompt+params+seed + a pinned content hash; CI re-run diff empty or documented. Measure: re-run hash equivalence in CI. (AX-002)
  • NFR-005 — Anon/pseudo metric separation. Threshold: zero code paths merge anonymization and pseudonymization metric families into one headline score. Measure: static check + reviewer audit. (AX-004; boolean)
  • NFR-006 — No real PII. Threshold: zero real-PII leakage findings (checksum-valid identifiers not from a declared generator; real public-figure name+contact; real secrets) on corpus + fixtures. Measure: /dev-assist-validate --sensitive-data + security-sast reviewer. (AX-001; release-blocking)
  • NFR-007 — Adversary version-pinning. Threshold: every RRS figure records adversary model+prompt+decoding+seed and is reproducible within CI tolerance (± a stated epsilon on re-run). Measure: artifact-field presence + re-run check. (UC-05/FR-007)

Performance / cost (consumer-facing)

  • NFR-008 — Calibration target. Threshold: ECE reported per entity class; reference/baseline detectors target ECE ≤ 0.05 (reported, not a submitter pass/fail). Measure: ECE computation on dev split. (UC-03; R10-validated)
  • NFR-009 — Eval cost budget + cheap-adversary mode. Threshold: full RRS-adversary run cost per system is documented; a deterministic/offline cheap-adversary mode is available at $0 external cost. Measure: cost report + offline-mode test. (N2; R10-validated)
  • NFR-010 — Scorer throughput + runtime dimension. (R10 → PERSONA-STRATIFIED; split into a/b/c)
    • NFR-010a (no gate): every run reports rec/sec per detector-class (regex / spaCy-NER / transformer / LLM); transformer/LLM detectors exempt from any throughput floor. Measure: per-class rec/sec in run-record.
    • NFR-010b (runtime path): lightweight detection path ≥5,000 rec/sec on 8-core AND report p50/p95/p99 per-record latency + streaming/chunked input. (real_user_needed: true — Pass-2 the number.)
    • NFR-010c (batch): document warehouse-scale full-scan wall-clock + record-size; recommend sampling above a stated row count. (N4; Pass-2.)

Coverage / completeness

  • NFR-012 — Croissant/HF loadability. Threshold: Croissant file validates against the spec AND loads via the HF datasets loader (not mere presence). Measure: validator + load test in CI. (UC-12; boolean)
