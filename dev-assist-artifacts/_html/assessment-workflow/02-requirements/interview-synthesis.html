1. Convergent priorities (multi-persona, gating)

Ordered by breadth + strength of convergence. A signal is UNANIMOUS when all 6 named it, HIGH-CONVERGENT when all 3 HIGH personas named it.

C-1 · Audited stats path is non-negotiable — quarantine significance.py (P1 precondition) — UNANIMOUS, anxiety=strong

Every interviewee independently treated routing through the audited eval-data/stats core (paired.py + intervals.py) and quarantining the fabricated pii-rate-elo/analysis/significance.py (bootstrap se=metric*(1-metric)/100 + Gaussian noise L205-206; McNemar n_approx=100/pooled_sd=0.1 L271-281) as a walk-away trigger, not a preference. INT-01: "if I audit the significance code and find hardcoded n=100 or Gaussian noise … I walk away and I tell my colleagues." INT-02: "if any significance computation routes through significance.py … my paper is compromised." INT-03 (tool-builder, surprised himself): "matters to me … more than I expected … I'm publishing a number derived from noise." Threshold signal: INT-02 and INT-03 both demanded this be CI-enforced, not just documented — a test asserting the audited path is always taken and the fabricated path is unreachable from the run surface. → sharpens UC-17, Open Item 1; → R4 (new NFR candidate: run-surface quarantine assertion test).

C-2 · Dataset-seam regression contract — silent drift is a confirmed historical burn (P2 precondition) — HIGH-CONVERGENT + INT-04/05, anxiety=strong

The seam reconciliation to v2.0.0 / 575,604 / CC0 / annotations with a regression contract (version + record-count + 63-type count + schema fingerprint + dataset content hash) is confirmed by 5 of 6, and two reported a real multi-period burn from silent dataset drift: INT-01 lost "a 6-month reanalysis"; INT-03 "spent a week tracing which changes drove the delta" after shipping a model-card number computed against the wrong version. INT-02 named it "the single most likely trust-killer." Threshold signals: (a) the contract must catch same-count substitution (content hash), not only count/version reverts (INT-03, GAME-07); (b) INT-02 wants the contract emitted as a structured field in the run-record JSON — assertable in a paper's methods section, not just a crosswalk doc; (c) INT-03 wants corpus-vs-model delta attribution when a score moves across runs. → sharpens UC-21, C1; → R4 (new FR candidate: run-record regression-contract field; delta attribution).

C-3 · Per-metric CIs with a deterministic interval-selection rule — UNANIMOUS (incl. the oracle lens) — pull=strong

A CI on every published proportion is the cheapest credibility the benchmark can buy, and all 6 confirmed it — including INT-06, who reframed it for the oracle use ("if I know the oracle has 94% recall on SSN (Wilson CI 91–96%) I can calibrate my false-negative rate"). INT-04 has built Wilson/Clopper-Pearson "once from scratch; it took two days and a stats review." Threshold signal: the interval-selection rule must be disclosed (Wilson default / Clopper-Pearson small-n/boundary / paired-bootstrap for differences) — INT-01 and INT-05 both flagged that an undisclosed rule makes the CI column ambiguous. INT-05 lists per-metric CI with disclosed method among the first-six hard send-back triggers. → confirms UC-17 (a), AX-003, Open Item 5.

C-4 · Paired test before any system-vs-system claim, with declared multiplicity family — HIGH-CONVERGENT + INT-05, push=strong

Eyeballed F1-deltas are a confirmed rejection vector: INT-01's delta "evaporated (p=0.14)" under McNemar in revision; INT-02's ACL submission was killed by Reviewer-3 ("delta is within noise, no significance test") at a 6-week cost. All three HIGH personas + INT-05 want McNemar + paired bootstrap gating directional claims. Threshold signal (sharpens AX-005): INT-01 and INT-02 independently demanded the multiplicity family be declared explicitly — the two inference families (exploratory per-cell uncorrected vs confirmatory pairwise Holm-Bonferroni with family size stated) must be in the axiom/report text, not only in code, "because reviewers will ask and the author needs to be able to explain it without reading source code" (INT-01). → confirms UC-17 (b), UC-23 (b); sharpens AX-pii-anon-005.

C-5 · Named shortfall on under-powered cells (DF-3) — UNANIMOUS, and the study's strongest delight — pull=strong

DF-3 resolved with zero dissent: all 6 chose show-greyed/flagged-with-the-exact-shortfall-named, and all 6 explicitly rejected both "omit" (a lie of omission; "looks like you had power you didn't" — INT-01; "looks like the pipeline failed to run on that type" — INT-05) and "show like any other number" (it gets cited unqualified). This is the single most-praised feature across the cohort and the resolution of the DF-3 fork. Threshold signals: (a) the shortfall must be expressed in REALIZED positive counts, not target_n labels — INT-03: "'short by 47 realized positives vs ADEQUATE threshold' is actionable; 'needs more data' is not"; INT-06 wants it per (entity-type × language) cell ("need N more positives on IBAN/es-ES"); (b) the distinction UNDER_SAMPLED vs CORPUS_LIMITED vs EMPTY matters (INT-03, INT-06 — fixable-by-drawing-more vs irreducible); (c) INT-01/05 require the label be structurally part of the number / non-strippable, because "the stamp gets lost in the filing" (INT-04's Japanese-data case: he flagged it verbally, the reviewer "cited the number unqualified in their risk memo"). → confirms UC-16, UC-23 (d); resolves DF-3 (Open Items 3,5).

C-6 · Non-strippable synthetic-only caveat, enforced by construction — UNANIMOUS, anxiety=strong (assurance/procurement) — pull=strong

3. How the decision-forks resolved (DF-1 … DF-5)

DF-1 · Default mode (powered sample vs full corpus) — SPLIT BY USE, NOT BY PERSONA. The locked default holds, but the labelling/parity requirements sharpen.

This is the one genuine disagreement in the study, and it splits on citable-vs-operational use, not on persona identity:

  • Powered-sample-as-default is CORRECT for the operational/cost-bound path — confirmed by INT-02 (when LLM-adversary cost binds), INT-03 (per-PR / CI; "I'd probably never run the full corpus"), INT-04 (pre-screen; "a cost I can't justify … every time"), INT-06 (oracle calibration; "whole corpus every time would be overkill"). The load-bearing condition all four attached: the power verdict must be named per cell — INT-02: "the wrong default is full-corpus-but-unlabeled-power — that's false confidence"; INT-03: "if the label says ADEQUATE and the CI is shown, I'll trust it as a gate."
  • Full-corpus is REQUIRED for the citable/headline/filing number — INT-01 (a reviewer "will immediately ask 'why didn't you run the whole thing?'"), INT-03 (model-card headline; "'sampled but powered' requires an explanation I'd rather not owe every user"), and most strongly INT-05 pushed back on the locked brief: for filing-grade evidence he wants full-corpus as the default, powered-sample as an explicitly-labelled cost-optimization mode, because power-tier explanation to a regulatory advisor "adds a layer of explanation that should not need to exist."

Resolution (consistent with the locked brief + G2/G3): keep powered-representative as the CLI default and FULL = the citable leaderboard, but the requirement set must make the citable-vs-pre-screen distinction first-class and unmistakable: (a) the representative run is ALWAYS labelled with its power verdict (SMALL/ADEQUATE/LARGE) + named shortfall, never silently LARGE (G3); (b) a run-type / filing-grade designation selects which mode backs a citable claim (this is the same scoping mechanism DF-2 needs — see below). INT-05's pushback is first-contact assurance signal, not a mandate to flip the default (R2 caveat) — but it must be carried to R6/R7 as a candidate refinement for the filing-grade run-type, and to Pass-2 ("I'd want to verify whether regulators in practice accept a well-labeled powered-sample artifact" — INT-05's own hedge). → sharpens UC-19, Open Items 3,4, G2/G3; carry INT-05's full-corpus-for-filing pushback to R6/R7 + Pass-2.

DF-2 · Pre-registration (mandatory vs opt-in) — RESOLVED: opt-in, run-type-scoped. Universal commitment is manifest-reproducibility.

Unanimous (§1 C-7): opt-in for dev/internal, enforced for the high-stakes run-type. The persona-specific "stakes line": INT-01/02/03 → leaderboard/publication submission; INT-05 → filing-grade / Art-11; INT-04 → formal procurement doc or compliance filing; INT-06 → formal comparative security report. The disconfirming probes paid off: 3 interviewees independently warned mandatory-for-all-runs would cause avoidance — INT-02 "would kill adoption for the exploratory loop," INT-03 "developers to bypass the tool," INT-06 "route around the harness entirely," and INT-05 warned teams would "avoid the formal mode and file development outputs instead, which is worse." Requirement (net-new mechanism): the workflow must support a run-type designation (e.g., dev / smoke / leaderboard-submission / filing-grade) that scopes pre-registration enforcement (and the AX-005 bar — see §5), rather than a single global on/off. INT-01/03 want this exposed as a CLI flag/preset, "not a philosophy" (INT-03). When on: git-commit-anchored + pushed-to-remote + hash-chained into the first run-record, immutable, with run-lineage count disclosed (re-roll-until-favorable visibility). → resolves DF-2 (Open Item 6); confirms UC-18; → R4 (new FR: run-type designation scoping pre-reg + AX-005 enforcement).

DF-3 · Under-powered reporting — RESOLVED with zero dissent: greyed/flagged + named shortfall in realized positives. (Full detail in §1 C-5.)

The cleanest fork in the study. All 6: show-greyed-with-named-shortfall; reject omit AND show-normally. Realized positives not target labels; UNDER_SAMPLED/CORPUS_LIMITED/EMPTY distinction; structurally non-strippable. → resolves DF-3 (Open Items 3,5); confirms UC-16, UC-23 (d).

DF-4 · Real-data correlation slice — RESOLVED: the named credibility unlock; use synthetic now WITH the ceiling caveat, do NOT block v0.1 on it.

Unanimous that the real-corpus correlation study (vs i2b2-2014 / TAB; cycle-1 UC-13) is the single highest-leverage upgrade — and unanimous that they'd use the synthetic numbers now with an explicit ceiling caveat rather than wait. The persona-specific framing of what the study unlocks:

  • INT-01 (clinical): upgrades a supplementary stress-test to a primary result ("Rankings track i2b2-2014, Spearman ρ=… [CI]" is "publishable as a primary result at ACL or JAMIA"). The synthetic-only ceiling is the dominant anxiety and "the single biggest reason a skeptical reviewer could dismiss results."
  • INT-02 (methods): upgrades an ablation-grade claim to a generalization claim; would wait for a primary comparison paper but not for an ablation.
  • INT-03 (tool-builder): upgrades "CI gate only" to "citable model-card score" at Kendall-τ > 0.8.
  • INT-04 (priv-eng): the unlock is stakeholder-facing — moves "we think these numbers are predictive" to "shown to track real-data behavior" for security leadership; he flags that powered + synthetic is genuinely harder to sell than powered alone, so the correlation study must at least be named-and-pending in the report.
  • INT-05 (assurance): upgrades "evidence scaffolding" to "supporting evidence for a real-world capability claim"; without it the ceiling statement must read "these results do not constitute evidence of real-world re-identification resistance."
  • INT-06 (red-team): the study tells him how much to trust the oracle floor (synthetic recall vs real-world adversarial recall); discounts synthetic by an unknown factor until then.

Resolution: carry cycle-1 UC-13 real-data correlation as the top credibility unlock to Requirements + Testing Pass-2, out-of-band, NOT v0.1-blocking (gated on external DUA). The non-strippable synthetic-only caveat (C-6) is the load-bearing v0.1 substitute, and INT-04's "correlation study named-and-pending" flag is a → R4 (report requirement). → confirms Open Item 11; sharpens UC-23, C3 (the ceiling-statement template).

DF-5 · Leaderboard hygiene / anti-gaming — RESOLVED: blind submission + held-out-label separation + provenance stamp + contamination disclosure; arms-length governance is a hard gate.

Converged across the personas whose threat-model justifies it (INT-02 consumer-side, INT-03 submitter-side, INT-05 assurance-side, INT-06 oracle-side):

  • Contamination is the hardest dismissal to disarm (INT-03; the corpus is public synthetic → train-on-test). Mechanism: per-system contamination_status with "unknown" rejected/flagged, plus a signed attestation that held-out labels were not exposed (INT-03's 6th AX-005 element). INT-02: a leaderboard that accepts contamination_status: unknown "is not trustworthy."
  • Blind submission (evaluator runs inference, not submitter; held-out labels genuinely held out) — INT-03 would accept signing an attestation rather than open-sourcing weights; the vendor-gaming sub-archetype's own incentive (avoid disclosing training data / held-out set) is the forcing function INT-05 names as the structural P-tool-vendor / P-complreviewer tension the governance must resolve explicitly.
  • Arms-length / neutral governance is inadmissibility-grade for the assurance consumer: INT-05 "rejected vendor self-benchmarks as inadmissible on two recent mandates"; "a tool vendor running their own benchmark is inadmissible regardless of methodology quality." INT-04 (procurement): vendor self-benchmarks are "inadmissible to my procurement process." Both want a named neutrality/governance statement (who controls the corpus, who holds the labels, who runs the eval) as a field in the run-record + every report page, not a general caveat. INT-05 adds: a managed conflict (academic group with a system in the leaderboard) needs explicit disclosure + a recusal record.

→ resolves DF-5 (Open Items 8,9,10); confirms UC-17 (d), UC-23; → R4 (governance NFRs: blind/provenance submission, contamination disclosure, neutrality statement field, recusal record).

  2. AX-pii-anon-005 universality vs run-type scoping. Adjudication: these are reconcilable via the run-type mechanism — the full AX-005 bar binds the published/leaderboard/filing run-types (satisfies INT-05), while smoke/dev runs suppress CI/p-value emission entirely (UC-20) rather than emit a sloppy number (satisfies INT-02's underlying worry — there is no un-rigorous number to mis-cite because there is no number). Confirm the exact per-run-type bar in R6/R7. (§5)

  3. AX-004 salience is persona-stratified, not universal. Adjudication: the boundaries hold (UC scope-boundary statements + MEI-06); the net-new in-scope asks are routed individually in §5. The coverage envelope / NOT_ASSESSED ask (INT-06) reinforces UC-16 DOM-03 and should be surfaced as a first-class artifact consumed by oracle callers, not just a reporter artifact.

  5. Citation-format gate (DOI) is HARD for the academic cohort, silent for others. INT-01 makes a Zenodo DOI a hard gate (won't cite a SHA in JAMIA/ACL); INT-02 confirms; INT-03/04/05/06 didn't raise it (CI-gate / procurement / oracle / filing uses don't need a DOI).
