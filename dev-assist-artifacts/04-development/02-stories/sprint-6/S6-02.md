## 2. Goal

Ship `src/pii_anon_datasets/leaderboard/policy.py`: a pure-stdlib submission policy over the S6-01
`LeaderboardStore`. `evaluate_submission(...)` returns a `PolicyDecision(allowed, published, reasons)`
applying the FR-023 controls: **opt-in publish** (`published` is True only if the submitter opted in AND
the submission is allowed), **rate-limit** (block once a submitter exceeds `max_submissions_per_epoch`
for the current epoch — counted from the store's prior `submitted` events), **held-out rotation epoch**
(reject a submission whose `declared_epoch` ≠ the current epoch — the held-out set rotates and stale-epoch
submissions are invalid), and a **contamination / duplicate check** (flag a `submission_hash` already
seen in the store). Deterministic, pure-stdlib (no clock/RNG); the policy only READS the store (the caller
appends the resulting event).

## 8b. Implementation spec (authoritative)

Pure-stdlib. Reads `store.events()` (filters prior `submitted` events); never appends. Deterministic.

```python
from __future__ import annotations
from collections.abc import Mapping
from dataclasses import dataclass

from pii_anon_datasets.leaderboard.store import EventType, LeaderboardStore

@dataclass(frozen=True)
class PolicyConfig:
    current_epoch: int = 0           # the active held-out rotation epoch
    max_submissions_per_epoch: int = 5

@dataclass(frozen=True)
class Submission:
    submitter: str
    submission_hash: str             # content hash of the submission artifact (for contamination/dup)
    declared_epoch: int
    publish_opt_in: bool = False

@dataclass(frozen=True)
class PolicyDecision:
    allowed: bool
    published: bool
    reasons: tuple[str, ...]         # e.g. ("rate_limit",), ("stale_epoch",), ("duplicate",); () if clean

def _prior_submitted(store: LeaderboardStore) -> list[Mapping[str, object]]:
    """Payloads of prior `submitted` events."""
    return [e.payload for e in store.events() if e.event_type is EventType.SUBMITTED]

def evaluate_submission(store: LeaderboardStore, submission: Submission,
                        config: PolicyConfig) -> PolicyDecision:
    """Apply the FR-023 controls; return a PolicyDecision. Pure-read over the store (no append)."""
    reasons: list[str] = []
    prior = _prior_submitted(store)

    # held-out rotation epoch: a submission must target the CURRENT epoch.
    if submission.declared_epoch != config.current_epoch:
        reasons.append("stale_epoch")

    # rate-limit: count this submitter's prior submissions in the current epoch.
    submitter_count = sum(
        1 for p in prior
        if p.get("submitter") == submission.submitter
        and p.get("declared_epoch") == config.current_epoch
    )
    if submitter_count >= config.max_submissions_per_epoch:
        reasons.append("rate_limit")

    # contamination / duplicate: a re-used submission_hash.
    if any(p.get("submission_hash") == submission.submission_hash for p in prior):
        reasons.append("duplicate")

    allowed = not reasons
    published = allowed and submission.publish_opt_in
    return PolicyDecision(allowed=allowed, published=published, reasons=tuple(reasons))
```

**Load-bearing invariants:** (1) **opt-in publish (FR-023)** — `published` requires BOTH `allowed` AND
`publish_opt_in`. (2) **anti-gaming active (NFR-014)** — rate-limit, held-out-rotation-epoch, and
contamination/duplicate are all enforced, each contributing a distinct `reason`. (3) **read-only over the
store** — `evaluate_submission` never appends (the caller records the outcome event). (4) **pure-stdlib +
deterministic (NFR-004 / AX-002)** — no clock/RNG; the decision is a pure function of (store events,
submission, config).
