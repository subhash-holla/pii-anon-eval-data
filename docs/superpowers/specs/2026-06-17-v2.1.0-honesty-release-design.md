## 0. Context

This is **Phase 1 of a 3-phase dataset-enhancement program** whose purpose is to strengthen
the NeurIPS Datasets & Benchmarks paper authored in the sibling `pii-anon-research-paper`
(`research-assist-artifacts`, Paper 1 of a 3-paper program). The program was scoped from the
2026-06-15 reconciled roadmap (`_meta/improvement-and-research-opportunities-2026-06-15.md`)
and SME fitness panel (`_meta/sme-dataset-fitness-2026-06-15.md`), reconciled against the
current state of the dataset (Tier-A analysis suite is already shipped in `results/tier-a/`).

| Phase | Version | Workstreams | This spec |
|---|---|---|---|
| **Phase 1** | `v2.1.0` | WS1 honesty release · WS2 credibility analyses · WS5 FR-027 protocol | ✅ **THIS** |
| Phase 2 | `v2.2.0` | WS3 special-category data · WS4 non-English expansion (all 4 targets) | separate cycle |
| Phase 3 | on `v2.2.0` | WS6 cloud McNemar + powered multilingual (budget-gated) | separate cycle |

**Phase 1 invariant: no regeneration of synthetic content, no re-scoring.** The honesty work only
*adds* metadata fields and re-stamps the version; synthetic text and gold spans are unchanged, so
the 11-detector leaderboard is NOT re-scored. The only new compute is a cheap, deterministic run of
three trivial sanity detectors on the English test split (WS2-B).

### Honesty axioms carried into every change (from `00-axioms/validity-axioms.yaml`)

- **AX-001** synthetic-only — every metric is precision on the synthetic distribution, NOT
  external validity, NOT a compliance certification.
- **AX-002** — NO Cohen's-κ / human-IAA may be introduced (corpus is template-generated).
- **AX-003** — disclose enrichment + label-map coverage ceilings.
- Additive, non-destructive: keep every existing key; add honest aliases + caveats + flags.

## 1. Goal & success criteria

**Goal:** ship a **local/working** `v2.1.0` that (a) makes the dataset's honesty *travel into the
shipped data and docs* (today the caveats live only in scorer code), (b) adds three cheap
credibility analyses the paper can cite, and (c) publishes a pre-registered external-validity
protocol — all with zero corpus regeneration. **Formal Zenodo DOI re-mint + HuggingFace publish are
deferred to Phase 2 (`v2.2.0`)** so we archive once; the paper cites the working version meanwhile
(PI decision, 2026-06-17).

**Done when:**

1. `load_dataset()` (jsonl.gz) **and** `dist/*.parquet` both carry the honest aliases, caveats,
   `legal_category`, `residual_quasi_identifier`, and `reg_hipaa_phi_present` fields.
2. The **content** version reads `2.1.0` across content touch-points; **publication metadata + DOI
   stay at the last archived release (`v2.0.0`)** with a clear working-version note (no Zenodo
   re-mint / HF push this phase); `scripts/check_version_sync.py` enforces both tiers.
3. `BASELINES.md` shows a cost-normalized axis and a clearly-separated "sanity bounds" block; the
   ranked **11-detector** leaderboard framing is unchanged.
4. `results/tier-a/contribution_tiering.{md,png}` exists.
5. `docs/external-validity-protocol.md` exists and is cross-linked; the FR-027
   `preregistration.md` + `copublication-terms.md` + `recruiting-checklist.md` are filled.
6. Full test suite green (incl. new `tests/test_honesty_fixes.py`), `ruff` clean, croissant
   round-trips, doc-drift + power gates pass, `dist/SHA256SUMS.txt` regenerated.
7. CHANGELOG `[2.1.0]` entry + MIGRATION.md `v2.0.0 → v2.1.0` section + `compat.to_v2_record()`.

**Explicitly OUT of scope (deferred to Phase 2/3):** Article-9 uplift, `_NON_PERSONAL`
records, non-English generation, the FR-027 *run*, cloud per-record McNemar, destructive field
renames (the additive aliases stand for v2.1.0; destructive renames are a later coordinated PR),
the real k-anonymity computation, the answerability harness, LLM Tier-3 adversary.

## 2. Component A — Honesty release (WS1)

### A.1 Record-level honesty transform (canonical)

**Decision (PI-approved):** honesty fields are applied at the **record level** so the jsonl.gz
source and the parquet dist stay consistent — not parquet-only.

- New module `src/pii_anon_datasets/honesty.py` exposing `apply_honesty(record: dict) -> dict`
  — additive, idempotent, pure (no RNG/clock). This is the existing `scripts/apply_honesty_fixes.py`
  logic lifted to operate on a record dict (it already manipulates a dict in-place).
- New migration `scripts/v2_0_0_to_v2_1_0.py` (mirrors `scripts/v1_3_0_to_v2_0_0.py`): streams the
  canonical corpus, applies `apply_honesty(rec)`, sets `rec["version"] = rec["schema_version"] = "2.1.0"`.
- `apply_honesty_fixes.py` is retained but refactored to call `honesty.apply_honesty` per row
  (single source of truth) and additionally stamp the parquet **file-level schema metadata**.

**Fields added** (exactly as `apply_honesty_fixes.py` already does — verified):

| Location | Added |
|---|---|
| `context_preservation.utility_metrics` | `token_overlap_jaccard_{masked,pseudonymized,llm_sanitized}` (alias of `semantic_similarity_*`); `_caveat` (UTIL_CAVEAT) |
| `context_preservation` | `legal_category` (per variant; pseudonymized & llm_sanitized = Art.4(5) STILL PERSONAL DATA); `residual_quasi_identifier`; `_caveat` (CP_CAVEAT — no variant anonymised under Recital 26) |
| `tier3_evaluation` | `exposure_index_prior` (alias of `re_identification_resistance_score`); `_caveat` (T3_CAVEAT — heuristic prior, not a measured attack) |
| `privacy_risk` | `_caveat` (PR_CAVEAT — k_anonymity_estimate is a QI-type-count proxy, null where QIs absent) |
| top-level | `reg_hipaa_phi_present` (= `reg_hipaa_safe_harbor`; models PHI-content presence, not the 18-identifier Safe Harbor standard) |
| file metadata (parquet schema + jsonl metadata sidecar) | `honesty_fixes_applied`, `crosswalk_disclaimer`, `exposure_index_note`, `reg_gdpr_note`, `ax_001` |

Every old key is preserved; old consumers keep working.

### A.2 Schema declaration

Update `src/pii_anon_datasets/data/pii_anon.schema.json` to declare the new fields under
`context_preservation` (+ nested `utility_metrics`), `tier3_evaluation`, `privacy_risk`, and the
top-level `reg_hipaa_phi_present`. The nested objects do not set `additionalProperties:false`, so
this is additive-compatible; declaring them makes the fields discoverable + validated.

### A.3 Re-export + release artifacts

1. `pii-anon export --format parquet` → `dist/pii_anon.parquet` (+ the `dist/hf/data/*.parquet`
   split files) from the migrated source.
2. Update the croissant builder (`src/pii_anon_datasets/distribution/…`, the `build_croissant`
   path) to declare the new fields; `pii-anon export --format croissant` → `dist/croissant.json`.
   croissant content `version` = `2.1.0`, but its `citeAs`/DOI stays the `v2.0.0` archival
   (Phase-2 re-mint).
3. `pii-anon export --format card --baselines results/baselines/tier1-en-all/baseline_results.json`
   → `dist/README.md`.
4. Regenerate `dist/SHA256SUMS.txt` (re-hash every `dist/*` artifact).

### A.4 Version bump (two-tier) + drift guard

**Tier 1 — content version → `2.1.0`** (describes the schema/corpus content): `pyproject.toml:7`
(source of truth), `README.md` (title+schema note), `DATASHEET.md:1`, `BASELINES.md:1`,
`CHANGELOG.md`, `MIGRATION.md`, `RELEASE_CHECKLIST.md`,
`src/pii_anon_datasets/migration.py:19` (`SCHEMA_VERSION`),
`src/pii_anon_datasets/release/citation.py:31` (drives croissant content version).

**Tier 2 — publication metadata → stays at `v2.0.0` archival** (no DOI re-mint this phase):
`CITATION.cff`, `CITATION.bib`, `.zenodo.json` keep their `v2.0.0` `version` + the existing Zenodo
DOI, with an added note that `v2.1.0` is a working/unarchived version (Phase-2 re-mint). This keeps
the DOI honest — it must continue to resolve to the artifact it actually archived.

New `scripts/check_version_sync.py` is **two-tier**: asserts every Tier-1 location matches
`pyproject.toml`, and asserts every Tier-2 location matches the last-archived version constant
(so drift in either tier is still caught). Add to the Phase-1 quality gate.

### A.5 Doc disclosures (the "honesty travels" fix)

In README.md + DATASHEET.md, wherever utility/AI-era/Tier-3 is described:
- `semantic_similarity_*` is **token-overlap Jaccard**, not a semantic/embedding measure
  (`coherence_preserved_*` is an assumed constant; `information_loss_ratio` is an entity-type prior).
- Per-split AI-era counts: the README "250 each" is full-corpus; the **test split** is ~41/50/57/60;
  mark AI-era / adversarial sets as **scenario fixtures**, not a measured security eval.
- State prominently: **no record is demonstrated anonymised under Recital 26**; `tier3_risk_level`
  / RRS are priors, not measured attacks (point to `results/tier-a/measured_rrs.md`).

### A.6 Migration docs + tests

- `MIGRATION.md`: add `v2.0.0 → v2.1.0` section (what changed table, additive nature, run command,
  `compat.to_v2_record()` back-compat).
- `compat.py`: add `to_v2_record(rec)` that strips the v2.1.0 additions back to the v2.0.0 shape.
- `CHANGELOG.md`: new `## [2.1.0] - 2026-06-17` (Keep-a-Changelog; Added / Changed / Migration).
- New `tests/test_honesty_fixes.py`: additive-only (no key removed), idempotent (re-apply == apply),
  caveats present + non-empty, `legal_category` correctness, `residual_quasi_identifier` matches the
  `***-**-NNNN` partial-ID regex, round-trips through pyarrow.
- Update `tests/test_croissant.py`, `tests/test_parquet_export.py`, `tests/test_crosswalk.py` if they
  assert exact column/field sets (add the new `reg_hipaa_phi_present` column + new croissant fields to
  expected sets).

## 3. Component B — Credibility analyses (WS2)

### B.1 Cost-normalized leaderboard axis

- Extend `reporting/baselines.py::render_leaderboard_table()` to accept an optional
  `cost_per_detector: dict | None` and render `$/1k-records` and `cost/F2-point` columns.
- Compute via `baselines/cloud_cost.py::estimate_usd(provider, doc_char_lengths)` over the English
  test-split document lengths. Local detectors = `$0` (free / on-host). Definitions:
  - `$/1k-records = estimate_usd / (n_records / 1000)`
  - `cost/F2-point = ($/1k-records) / f2_micro`
- Emit the cost numbers into `baseline_results.json` (a `cost` block per detector) so the table is a
  pure render; document the June-2026 list-pricing basis (`CLOUD_DLP_COST.md`) inline.

### B.2 Negative-control + oracle sanity rows (separate block)

**Decision (PI-approved):** present in a labeled **"Sanity bounds"** block, separate from the ranked
11-detector leaderboard.

- New adapters following `baselines/regex_baseline.py`:
  - `baselines/null_baseline.py` — `label_map={}`, `detect → []` (expect F2 ≈ 0).
  - `baselines/always_person_name_baseline.py` — `label_map={"PERSON_NAME":"PERSON_NAME"}`,
    one span per whitespace token (expect low precision/F2).
  - `baselines/oracle_perfect_baseline.py` — reads gold from the record (expect F2 = 1.0).
- Contract extension for the oracle only: add backward-compatible record access. Orchestrator
  `_score_one` (`baselines/orchestrator.py:189`) calls
  `adapter.detect(text, model, record=rec)` **iff** `getattr(adapter, "wants_record", False)`,
  else `adapter.detect(text, model)`. Existing adapters are untouched; oracle sets `wants_record=True`.
- Register the three in `baselines/registry.py:DETECTOR_REGISTRY`; mark them as `sanity` (not
  `local`/`cloud`) so the main ranking excludes them.
- Run on the English test split (deterministic, cheap); render the sanity block in `BASELINES.md`
  under a clear "harness validity bounds — not ranked" heading.

### B.3 C1/C2/C3 contribution-tiering figure

- New `scripts/contribution_tiering.py` (house style of `scripts/free_bundle.py`) →
  `results/tier-a/contribution_tiering.{md,png}`. Tiers:
  - **C1 (delivered now):** the English 11-pipeline F2 benchmark + the v2.1.0 corpus.
  - **C2 (delivered now):** tri-dimensional slicing (per-entity-type / per-domain / per-language) +
    coverage-ceiling diagnostic.
  - **C3 (scoped future):** multilingual-at-power + real-data external validity (Phase 2/3) and
    Tier-2/Tier-3 grading (Papers 2/3).
- Sourced from the assessment trace chain
  (`research-assist-artifacts/00-positioning-assessment/assessment-2026-06-15.md` §3) + leaderboard.
  Matplotlib via the lazy `[viz]` import; `.png.SKIPPED` fallback if unavailable (existing pattern).

## 5. Sequencing within Phase 1

Three components are largely independent and can proceed in parallel, but the release artifacts
(A.3, A.4) must come last because they hash the migrated data + carry the new version.

1. **A.1–A.2** record-level transform + schema (foundation).
2. **B.1–B.3** analyses (independent; B.2 needs a cheap en-test run).
3. **C** FR-027 docs (independent; no code).
4. **A.5–A.6** doc disclosures + migration docs + tests.
5. **A.3–A.4** re-export + regen artifacts + version bump + sync guard (LAST).
6. Final gate run + CHANGELOG finalize.

## 7. Risks & mitigations

| Risk | Mitigation |
|---|---|
| jsonl ↔ parquet drift | Record-level canonical transform (A.1) is the single source; re-export parquet from migrated source. |
| Schema validator rejects new fields | Verified nested objects allow additive props; explicitly declare new fields (A.2). |
| Version-string drift (12 locations) | `scripts/check_version_sync.py` in the gate. |
| Sanity rows muddy the headline | Separate "sanity bounds" block; ranking excludes `sanity`-class detectors (B.2). |
| Croissant/export tests assert exact field sets | Update expected sets alongside the additive fields (A.6). |
| DOI/Zenodo re-mint scope | **Deferred to Phase 2** (mint once on `v2.2.0`). `v2.1.0` is local/working; publication metadata + DOI stay at the `v2.0.0` archival with a working-version note. No credentials touched, no HF push. |
| Cost numbers misread as measured billing | Label as June-2026 list-price *estimates* with the ×2 safety basis from `CLOUD_DLP_COST.md`. |
