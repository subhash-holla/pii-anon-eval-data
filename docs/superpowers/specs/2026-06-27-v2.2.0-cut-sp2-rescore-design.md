## 1. Substrate / output model — three scoring products

The re-score must feed five downstream artifacts that need different slices, so the run produces **three** scoring
products (not one). The aws-en scoring is **unified** (done once, as a per-record dump) to avoid double cost.

| Product | What runs | Where | Cost | Feeds |
|---|---|---|---|---|
| **P1 Multilingual aggregate** | 8 local detectors × all langs (`--languages all`) + cloud azure×10 / gcp×12 | VM (GPU) | azure $197.34 + gcp $0 | multilingual `by_language` F2 matrix (BASELINES.md) → **W5 Wilson-LB** |
| **P2 English all-11** | 8 local detectors × en (`by_entity_type`) + en cloud shards (reused from P1/P3) | VM local (or laptop) | $0 extra | en leaderboard · **W7 XW-BROAD′** · **W4 B-4** substrate |
| **P3 en-test per-record** | gliner (local) + **aws-en (cloud, once)** → per-record hits; aggregate aws-en row derived from these | VM | aws $25.62 (the only aws spend) | **W6 McNemar** · the aws cell of P1+P2 |

**aws-en unification (the cost-saver):** aws is en-only, so its only leaderboard contribution is the en cell.
SP-II scores aws-en **once** via `per_record_dump.py --detectors aws --language en`, then derives the aggregate
aws-en `DetectionScore` (P/R/F2 + Wilson CIs) from those per-record hits. That single scoring serves the en
leaderboard cell, the multilingual matrix aws column, **and** the McNemar aws arm — so W6 adds **$0**. azure/gcp
have no McNemar arm, so they use the normal aggregate cloud lane (`pii-anon baselines --cloud`).

**Wilson-LB without a per-record parquet (Path-B):** P1's `baseline_results.json` carries per-language
`DetectionScore.counts` (tp/fp/fn) in `by_language`. W5 sums tp/fn into ISO-15924 script buckets via `LANG_SCRIPT`
and computes `wilson_interval(tp, n_gold).low` — no multilingual per-record parquet dump is required (the existing
`multilingual_analysis.py` per-record path is superseded for this column).

## 3. Cross-cutting NFRs (this sub-project)

Inherits N1–N4 from the cut spec §2. SP-II-specific obligations:
- **N1 (checkpointing) — close the local-lane gap.** Today the local lane is restart-safe per-**detector**
  (`run_full_leaderboard.sh` skips a detector whose `baseline_results.json` exists) — a crash re-runs all 60
  languages. Extend to per-(detector,language) shard so a crash re-pays only the in-flight language. Cloud is
  already per-(provider,language) shard. No per-record checkpoint is added (out of scope; the shard is the unit).
- **N2 (reporting).** Each product writes a structured final report: per-detector/-language/-script F2 + Wilson
  CIs, record-error counts, wall-clock, and cloud **cost actuals** (not just the estimate). The VM run prints a
  run summary that is rsync'd back.
- **N3 (laptop-friendly).** All Phase-1/3 steps run `nice`+`caffeinate`, resumable.
- **VM cost-safety.** `provision_azure_gpu.sh` gains a post-run `az group list`/`az vm list` assertion that the
  resource group is deleted, and the orchestrator prints an explicit "VM still up — delete manually: <cmd>" if
  teardown didn't confirm (guards the trap-miss-on-crash path).

## 7. The five derived artifacts (detail)

- **W4 B-4** — `SANITY_DETECTORS = ("null","always_person_name","oracle")` (`baselines/registry.py`). Scored over
  the full en-test (31,048 rec) via the existing `score_detectors` path (oracle uses the `wants_record` seam).
  Rows: recall floor (null), precision floor (always_person_name), ceiling (oracle F2=1.0).
- **W5 Wilson-LB** — `wilson_interval(k=tp, n=n_gold, 0.95).low` (`src/pii_anon_datasets/stats/intervals.py`),
  integer tp/n_gold required (Path-B sums P1 `by_language` counts into script buckets). Column slots into the
  per-detector section of `multilingual_by_script.md`.
- **W6 McNemar** — `cloud_mcnemar.py` reads `{gold,hits_gliner,hits_aws}.parquet` from the P3 dump; uses
  `stats.paired.mcnemar(b,c)` + a seeded 2000-iter paired bootstrap on Δrecall. Both arms scored on the identical
  frozen en records (P3 content-hash guard ensures pairing).
- **W7 XW-BROAD′** — `coverage_decomposition.py` computes Pearson r(coverage-fraction, within-reach-recall) per
  crosswalk; the headline is the drop `r_overall − r_within`. Crosswalks live in the script (`XW_BROAD_GRANT`
  dict + `CROSSWALKS` tuple); XW-BROAD′ adds a third grant dict from an external taxonomy (§11). Reads per-type
  recall from the re-scored en `baseline_results.json` `by_entity_type`.
- **W8 2F** — §8.

## 10. Risks & mitigations

  `wilson_interval`'s integer requirement.

  true); the source is documented (§11).

## 11. Open content decision — XW-BROAD′ external source (PI approval at spec review)

XW-BROAD′ must be a crosswalk grant authored from an **external** PII taxonomy (independent of the author's
`label_maps_63.json`), to satisfy the EX-01b content-hash firewall. Proposed candidates (PI picks one or supplies
another):
- **NIST SP 800-122** PII categories (US federal definition of PII / linkable identifiers), or
- **HIPAA-18** Safe-Harbor identifier list (well-defined, citable), or
- **ISO/IEC 29100** privacy-framework PII categories.

The grant maps each detector's *dropped* native label (e.g. spaCy `DATE`, `NORP`; presidio `NRP`) to a canonical-63
type **iff the external taxonomy treats them as the same identifier class** — so the grant is defensibly external,
not the author's choice. The exact grant dict will be drafted in the plan from the chosen source and is itself the
EX-01b apparatus (documented provenance). Default if unspecified: **NIST SP 800-122** (broadest, US-standard,
freely citable).
