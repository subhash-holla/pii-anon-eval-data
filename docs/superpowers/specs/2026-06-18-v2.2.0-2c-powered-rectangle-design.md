2. **Bundled quick-wins** surfaced by the 2026-06-18 paper-artifact extension scan, all cheap and confirmed

DOI/HF re-mint, no headline leaderboard re-score — those are the `v2.2.0` cut's job, after 2C.

**Ground truth verified against the repo (2026-06-18):**
- Current corpus 578,469 records / 66 types / 60 languages / 19 ISO-15924 scripts. The 12 powered majors sit
  at ~34k–155k records; the 5 candidates sit at **ru 431, th 277, el 236, bn 229, he 229**.
- The committed lattice is built from the **pinned** `src/pii_anon_datasets/data/lattice_freq_snapshot.json`
  (source_version 1.3.0) by `stats.lattice.build_committed_lattice()`; the power gate
  (`scripts/validate.py:check_committed_cell_power` + `scripts/lattice_audit.py`) requires **every committed
  count-gated cell ≥ its tier target** (critical 1522 / standard 753 / long_tail 200, from `stats/power.py`).
  Current lattice = 733 cells (713 count-gated; LxE rectangle 492 = 12×41 frequent types).
- The generator's only language-keyed value pool is `NAME_DB` in `scripts/generate_records.py`: **ru** has
  native Cyrillic names; **th** is romanized Latin (like `hi`); **el/bn/he are absent** → English fallback.
  All non-name values (address/org/job/medical/IDs) are English/US across **all 60 languages** (incl. the
  existing powered majors zh/ja/ko/ar) — only person names are localized.
- `generate_lattice_fill.py` exists with `--dry-run` / `--max-records` and reads committed-lattice deficits
  (the 2C generation path). `entity_crosswalk._ART9_SPECIAL_CATEGORY` (frozenset, line 64) is the
  authoritative GDPR Art-9 set (distinct from the broader taxonomy `special_category` category, which also
  contains non-Art-9 types like VEHICLE_MODEL). `results/tier-a/honesty_fixes.md §2` lists B-6's two renames.

**Honesty axioms carried in** (`00-axioms/validity-axioms.yaml`): AX-001 synthetic-only; AX-002 no human IAA;
AX-003 coverage-ceiling. All metrics are synthetic-distribution precision.

## 2. Component 2C-core — powered-rectangle extension

### 2C.1 Languages & depth (LOCKED, PI 2026-06-18)
Power **ru (Cyrl), th (Thai), el (Grek), bn (Beng), he (Hebr)** into the **full** `language_x_entity_type`
rectangle (×41 frequent types, at each type's tier). Chosen for **script diversity** (6→11 writing systems);
generation cost is ~equal across candidates, so the script-maximizing set is the highest-narrative choice.

### 2C.2 Volume (LOCKED: gate-floor + margin)
Target **~21k records/language (~105k total)** = the positive-count gate floor (≈43,177 positives/lang =
16 critical×1522 + 25 standard×753, at ~2 counted positives/record) + ~7% margin. **Empirically calibrate**:
generate a ~5k-record probe, measure mean positives/record, set `--max-records` from the measured deficit —
NOT the 2.2 assumption. Do **not** chase parity-density (~34k/lang); the gate doesn't require it.

### 2C.3 Name pools (LOCKED: Option B — native names for el/bn/he)
Add `FIRST_NAMES_EL/BN/HE` + `LAST_NAMES_EL/BN/HE` (~84 entries) to `NAME_DB` in `scripts/generate_records.py`,
reaching name-pool parity with zh/ja/ko/ar. Source: public common-name lists (census/Wikidata), vetted to
generic/high-frequency only (no real-PII), source documented in the script. th stays romanized; th-upgrade →
cut. A new test asserts el/bn/he emit native-script person names.

### 2C.4 Snapshot regen + lattice rebuild (PRE-generation — the #1 hazard)
`build_committed_lattice()` reads the **pinned** snapshot, never live metadata. If the snapshot still says
ru=431 the new langs are silently dropped (false-PASS). Therefore: regenerate `lattice_freq_snapshot.json`
from the live corpus (so ru/th/el/bn/he register as head langs), rebuild `eval_lattice.json`, and **assert
`cell_count == 938` (17×41 + the unchanged remainder) BEFORE any generation**. (The headline-lock's frozen
63-type `label_maps_63.json` is independent of this — it pins 63 and is untouched here.)

### 2C.5 Generation (LOCKED: `generate_lattice_fill.py`)
Drive generation off the rebuilt lattice deficits via `scripts/generate_lattice_fill.py` (tested, lattice-
driven, handles incidental-positive overlap). `--dry-run` first to read the real deficit; use a **fresh SEED**
distinct from Art-9's `20260618`; emit to the exact filename `merge_and_rebuild.py` expects
(`pii_anon_lattice_fill.jsonl`).

### 2C.6 Wilson-LB (per-script lower bound)
Powering the 5 new langs adds gold to the Cyrillic/Thai/Greek/Bengali/Hebrew script cells (currently small —
Thai n=335, Cyrillic n=1,374). The refreshed `results/tier-a/multilingual_by_script.md` adds a **Wilson 95%
lower-bound** column per script so the SC-07 per-script floor claim is honest at small n. This is an analysis-
column tweak subsumed by the powering, not a separate generation step.

## 3. Component B-5 — per-record `art9_special_categories[]`

A clean machine-readable stratification key for the "Art-9 recall 0/3 by construction" finding. **Pure
derivation** (no generation): for each record, `art9_special_categories` = `sorted({a["entity_type"] for a in
record["annotations"] if a["entity_type"] in entity_crosswalk._ART9_SPECIAL_CATEGORY})`. Applied as a build-
chain enrich step (so it rides the rebuild and flows into all splits/subsets); declared in
`pii_anon.schema.json` and the croissant metadata. A test asserts: records with an Art-9 annotation carry the
type in the array; records without carry `[]`; the array ⊆ `_ART9_SPECIAL_CATEGORY`.

## 4. Component B-6 — apply the two logged-but-unapplied honesty renames

Per `results/tier-a/honesty_fixes.md §2`, applied **additive-first** (emit the honest name now; deprecate the
old name over one version — the same pattern the v2.1.0 honesty release used for its sibling renames):

- **`coherence_preserved_*`** (a hardcoded `True`, zero-variance — currently inflates utility as a fake
  measurement) → **`coherence_assumed=true`** (chosen over silent removal: it honestly records that coherence
  is *assumed by construction*, not measured — the same epistemic-honesty stance as the v2.1.0 renames).
  Readers: `src/pii_anon_datasets/honesty.py`,
  `pii_anon.schema.json`, `scripts/enrich_context_preservation.py`, `scripts/enrich_llm_sanitized.py`.
- **`k_anonymity_estimate`** → **`qid_type_count_risk_label`** (we take the rename, not the new computation).
  Readers: `honesty.py`, `pii_anon.metadata.json`, `pii_anon.schema.json`, `scripts/enrich.py`,
  `scripts/migrate_v1_to_v2.py`, `scripts/generate_coverage_fill.py`, `scripts/generate_records.py`,
  `tests/test_honesty_fixes.py`, `tests/test_compat_v2.py`.

`honesty.py` is the single-source honesty module; route the renames through it. Existing tests
(`test_honesty_fixes.py`, `test_compat_v2.py`) are updated to the new names; back-compat for the deprecated
old name is retained for one version (consumed at load, disclosed). Applied during the rebuild's honesty
re-apply pass so the new records (and the re-derived splits/subsets) carry the honest names.

## 5. Component B-7 — per-jurisdiction identifier-type count metadata

The H-01/CL-01 claim guard requires reporting how many of the 66 types are national/jurisdiction-specific
identifiers and conceding the dataset does **not** claim per-jurisdiction completeness. There is no existing
jurisdiction classification in the taxonomy (categories are semantic, e.g. `contact`). Add a small **curated
list** of the jurisdiction-specific identifier types (e.g. `SOCIAL_SECURITY_NUMBER`, `DRIVER_LICENSE_NUMBER`,
`PASSPORT_NUMBER`, `NATIONAL_ID_NUMBER`, `TAX_ID`, … — exact list finalized in the plan) and a derived
**count** field in `pii_anon.metadata.json` + croissant + a DATASHEET line, **explicitly marked
non-exhaustive** ("N of 66 types are jurisdiction-specific national identifiers; coverage is illustrative, not
a completeness claim"). A test pins the count == len(the curated list) and that the list ⊆ the canonical 66.

## 6. Honesty / disclosure expansion

Required for the strengthened multilingual claim to be honest (the extension scan flagged these as currently
undisclosed beyond Art-9). Add to README/DATASHEET:
1. **All-language value anchoring:** non-name PII values (addresses, organizations, occupations, medical,
   identifiers, financial) are English/US-anchored synthetic across **all 60 languages**; per-language value
   localization is deferred to 2D.
2. **Romanized names:** hi (and th) person-name values are romanized Latin, not native-script.
3. **RTL limitation:** he records mix RTL Hebrew names with LTR Latin identifiers/emails/URLs.
4. **Publishable claim wording:** "a committed evaluation lattice powering 17 languages across 11 writing
   systems (… Cyrillic, Thai, Greek, Bengali, Hebrew) to statistically-calibrated positive-count targets
   (critical n≥1522, standard n≥753) over 41 frequent entity types" — with caveats 1–3 attached. AX-001/AX-002
   stand. Do not let "11 writing systems" imply 11 localized locales — it is script-tagged records + script-
   native person names, not value-level locale realism.

## 7. Build sequence (ordered — one rebuild, all components)

1. **Code/config foundation:** 2C.3 NAME_DB pools (el/bn/he); B-5 enrich step; B-6 renames in `honesty.py` +
   enrichment scripts + schema + croissant; B-7 curated jurisdiction list + metadata field. (All before
   generation so new records are born correct.)
2. **Snapshot regen + lattice rebuild (PRE-generation):** regenerate `lattice_freq_snapshot.json`; rebuild
   `eval_lattice.json`; **assert cell_count == 938** before continuing.
3. **Generate:** `generate_lattice_fill.py --dry-run` (read deficit) → calibrate `--max-records` from a 5k
   probe → generate to `pii_anon_lattice_fill.jsonl` (fresh SEED).
4. **Merge & rebuild:** `merge_and_rebuild.py` (content-hash dedup).
5. **Enrich chain (serial, set -e):** `enrich.py` → `enrich_context_preservation.py` →
   `enrich_nested_and_ai_era.py` → `enrich_behavioral_signals.py` → `enrich_llm_sanitized.py` → honesty
   re-apply (`v2_0_0_to_v2_1_0.py`) → B-5 art9-array step (or fold into enrich). **Gotcha:**
   `enrich_nested_and_ai_era.py` is NON-idempotent (generates 1000 fresh AI-era records each run) — delete
   `pii_anon_ai_era.jsonl` before re-running; assert AI-era ≈1000 post-build.
6. **Canonicalize → validate → subsets:** `canonicalize_scripts.py` (BEFORE subsets) → `validate --lattice`
   (expect PASS, 918 cells) → `generate_subsets.py` (re-derives all splits/subsets from the rebuilt main).
7. **Tests + docs + analyses:** re-pin lattice test constants; B-5/B-6/B-7 tests; refresh
   `multilingual_by_script.md` (+ Wilson-LB column) and `multilingual_by_language` coverage; expand
   README/DATASHEET disclosure; regenerate `MANIFEST.sha256`; CHANGELOG `v2.2-dev` entry.
8. **Re-score posture:** a lightweight **5-lang degeneracy-check** re-score during generation (confirm the new
   cells are detector-discriminative, not trivially-hit); the full 11-detector headline leaderboard re-score
   stays deferred to the v2.2.0 cut (cloud budget-gated → Phase 3).

## 9. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Stale snapshot → new langs silently dropped → false-PASS validate | Regenerate snapshot in step 2; assert `cell_count == 938` BEFORE generating. |
| `--max-records` below the true deficit → gate FAILS with residual deficits | `--dry-run` first; calibrate from a 5k probe, not the 2.2 assumption. |
| SEED reuse vs Art-9 → identical records silently deduped → deficit unclosed | Use a fresh SEED distinct from `20260618`. |
| `enrich_nested_and_ai_era` non-idempotency doubles AI-era records (bit 2A) | Delete `pii_anon_ai_era.jsonl` before any enrich re-run; assert AI-era ≈1000 post-build. |
| B-6 renames break readers (8+ files) | Additive-first (emit honest name, keep deprecated alias one version); update the 2 honesty tests in the same change. |
| el/bn/he names unrealistic / privacy leak | Public common-name lists, vetted to generic/high-frequency; document source; AX-001 disclosed. |
| "11 writing systems" misread as full localization | Disclosure §6 caveats 1–3; claim wording is script-coverage of person names + script-tagged records. |
| 2C disturbs the headline-lock frozen 63 registry | label_maps_63.json pins 63 + is taxonomy-decoupled (guard test); 2C touches the live lattice/corpus, not the frozen registry — re-run both headline-lock `--check`s in the gate. |
