## 0. Context

This is **the first sub-project of Phase 2** of the dataset-enhancement program (see
`docs/superpowers/specs/2026-06-17-v2.1.0-honesty-release-design.md` for Phase 1, now complete).
Phase 2 (→ `v2.2.0`) was decomposed because the maximal multilingual scope is too large for one spec:

| Sub-project | Scope | This spec |
|---|---|---|
| **2A — special-category + scope** | +3 Art-9 types (63→66), up-sample political/religious/ethnicity to ≥400, generate `_NON_PERSONAL` records, reconcile schema drift + ETHNICITY sensitivity | ✅ **THIS** |
| **2B — script canonicalization** | Canonicalize the `script` field to ISO 15924 across the corpus (fix mislabels + dual-naming) | ✅ **THIS** |
| 2C — powered-rectangle extension | Power ~3–5 more priority languages to ≥753 gold | separate cycle |
| 2D — tail-lift + breadth | Lift the ~48 tail languages + new languages (community pathway) | staged, later |
| 2E — non-English utility metrics | Real semantic/answerability metrics for non-English | **deferred to Paper 2** |

**Version posture (load-bearing).** 2A+2B land as **working increments on the branch** — content version
stays `2.1.0`, no DOI/HF re-mint. The single **`v2.2.0` cut** (content version bump + the consistent
local+cloud leaderboard re-score + the Zenodo/HF re-mint) happens **after 2C**, when the corpus composition
is final. The taxonomy reaching 66 types is part of the in-progress v2.2.0; tests assert 66 while the
per-record `version` field stays `2.1.0` until the cut (working-branch state, not a release).

**Ground truth verified against the corpus (2026-06-18):**
- The corpus uses **exactly the canonical 63** entity types (no undercount, no extras). The JSON-schema
  enum has **86** types — 23 are unused cruft (incl. stale `UNION_MEMBERSHIP` / `GENETIC_MARKER`).
- `POLITICAL_OPINION` / `RELIGIOUS_BELIEF` / `ETHNICITY` ≈ **200 each** today (not the SME's 29/49/40).
- The `script` field is a naming mess: ISO codes + human-readable duplicates (`Cyrl`+`Cyrillic`,
  `Beng`+`Bengali`, …) + genuine `Latn` mislabels (`my`/`ta`/`te`) + ambiguous `CJK`.

**Honesty axioms carried in** (from Phase 1 / `00-axioms/validity-axioms.yaml`): AX-001 synthetic-only;
AX-002 no human-IAA; additive-honesty fields stay; all metrics are synthetic-distribution precision.

## 1. Goal & success criteria

**Goal:** close the Article-9 special-category coverage gap and make `reg_gdpr` discriminative (2A), and
fix the `script`-field inconsistency (2B) — strengthening the "comprehensive PII benchmark" and
data-quality stories the paper rests on — using the existing deterministic lattice machinery.

**Done when:**

1. The canonical taxonomy is **66 types** (`SEXUAL_ORIENTATION`, `TRADE_UNION_MEMBERSHIP`, `GENETIC_DATA`
   added as `special_category` / long-tail), and `taxonomy.ENTITY_TYPE_COUNT == 66` derives everywhere.
2. The 6 Art-9 types (3 new + political/religious/ethnicity) each have **≥400 positive spans**, generated
   across the **12 powered languages** (en + 11 majors).
3. **≥400 `_NON_PERSONAL`-only records** exist and `reg_gdpr` is discriminative (a powered out-of-scope
   set; `crosswalk_record` emits OUT_OF_SCOPE for them).
4. `ETHNICITY` annotations carry `sensitivity_class = "sensitive_attribute"` (Art-9 consistent).
5. The JSON-schema enum equals **exactly the canonical 66** (3 added; 23 verified-unused cruft removed).
6. `entity_crosswalk._ART9_SPECIAL_CATEGORY` includes the 3 new types; the crosswalk disclaimer says 66.
7. Every record's `script` field is a **valid ISO 15924 code** derived from its language (mislabels fixed,
   duplicates collapsed); the generator's `SCRIPT_MAP` is language-complete; the "writing systems" headline
   reflects the true canonicalized count.
8. **2A local re-score:** the 8 local detectors are re-scored on the new English test split; the
   per-entity-type table (now 66 types) and coverage-ceiling analysis are refreshed, showing the 3 new
   Art-9 types at ≈0 detector recall (the coverage-ceiling story). Labeled **"v2.2-dev local re-score"**;
   the consistent local+cloud headline leaderboard is the `v2.2.0` cut's job.
9. `pii-anon validate --lattice` PASSES (all committed cells incl. the new Art-9 + non-personal targets);
   full `pytest` green (updated 63→66 / long_tail 10→13 constants); `ruff` clean on changed files.
10. Docs updated: README/DATASHEET/TAXONOMY (66 types, the 3 Art-9 types, discriminative `reg_gdpr`,
    ISO-15924 scripts), CHANGELOG `[Unreleased]`/`v2.2-dev` entry.

**Explicitly OUT of scope:** 2C/2D/2E; the cloud re-score; the content-version bump to 2.2.0 + DOI/HF
re-mint (all at the `v2.2.0` cut); per-language Art-9 *value* localization beyond English-anchored synthetic
values (disclosed; deeper localization is 2D); real non-English utility metrics (2E/Paper 2).

## 2. Component 2A — Special-category + scope

### 2A.1 Taxonomy (single source)

`src/pii_anon_datasets/taxonomy.py` — add 3 entries to `ENTITY_REGISTRY` (map each to `"special_category"`)
and to `_LONG_TAIL_TYPES`. `ENTITY_TYPE_COUNT`, `CATEGORIES`, and the risk-tier partition auto-derive
(long_tail 10→13, total 63→66).

### 2A.2 Crosswalk

`src/pii_anon_datasets/compliance/entity_crosswalk.py` — add the 3 to `_ART9_SPECIAL_CATEGORY`; update
`CROSSWALK_DISCLAIMER` "63"→"66". `_NON_PERSONAL` is unchanged (the 3 new types are personal).

### 2A.3 Schema reconcile

`src/pii_anon_datasets/data/pii_anon.schema.json` — make the entity-type enum **exactly the canonical 66**:
add the 3 Art-9 types; remove the 23 unused cruft entries **after** a full-corpus scan confirms zero records
use any of them (BLOCK + report if any are used — that would mean the taxonomy undercounts and the cruft
list must be revised). Drops the stale `UNION_MEMBERSHIP` / `GENETIC_MARKER` in favor of the canonical names.

### 2A.4 Value emitters + ETHNICITY sensitivity

`scripts/lattice_targeting.py` — add 3 emitters to `EMITTERS` producing curated synthetic Art-9 values
(`SEXUAL_ORIENTATION`: orientation terms; `TRADE_UNION_MEMBERSHIP`: union-membership statements/union names;
`GENETIC_DATA`: synthetic gene/variant/test-result phrasings). Enrich the value pools for
`POLITICAL_OPINION`/`RELIGIOUS_BELIEF`/`ETHNICITY` so ≥400 spans aren't near-duplicates. Values are
**English-anchored synthetic** (disclosed — per-language Art-9 localization is 2D). Ensure `ETHNICITY`
annotations are emitted with `sensitivity_class = "sensitive_attribute"` (verify in the emitter + the
generator path; fix `TAXONOMY.md` if it says otherwise).

### 2A.5 Generation targets (lattice machinery)

- Set the **generation target** for each of the 6 Art-9 types to **≥400** (above the long_tail 200 gate
  floor), distributed across the 12 powered languages. Exact mechanism — a per-type override in
  `lattice_freq_snapshot.json` vs a fill target above the tier floor — is determined in the plan by reading
  `stats/lattice.py` + `generate_lattice_fill.py`; the gate floor stays long_tail (200), we generate to 400.
- Add a committed **non-personal cell** (or a generation target) for **≥400 `_NON_PERSONAL`-only records**
  (entities drawn only from `ORGANIZATION_NAME`/`URL`/`INVOICE_NUMBER`/`VEHICLE_MODEL`/`TIMESTAMP`), tagged
  so `crosswalk_record` emits `reg_gdpr = OUT_OF_SCOPE`.
- Rebuild `eval_lattice.json` via `stats/lattice.build_committed_lattice()` (auto-includes the 3 new types
  as long_tail cells), then `scripts/generate_lattice_fill.py` (deterministic, seeded) → new records.

### 2A.6 Build chain

`merge_and_rebuild.py` → `enrich.py` → `enrich_context_preservation.py` → `enrich_nested_and_ai_era.py` →
`enrich_behavioral_signals.py` → `enrich_llm_sanitized.py` → **honesty re-apply** (`scripts/v2_0_0_to_v2_1_0.py`
keeps the new records honest + version-stamped) → `validate.py` → `generate_subsets.py`. New records flow
into all splits/subsets automatically (stratified).

### 2A.7 Tests + docs

Update the count constants: `tests/test_taxonomy.py` (63→66), `tests/test_power.py` (long_tail 10→13;
the `==ENTITY_TYPE_COUNT` asserts auto-pass), `tests/test_lattice_targeting.py` (EMITTERS 63→66),
`tests/test_entity_crosswalk.py` (derived), schema/croissant/dataset-card count asserts (auto from
`ENTITY_TYPE_COUNT`). README/DATASHEET/TAXONOMY: 66 types + the 3 Art-9 types + the discriminative `reg_gdpr`
+ the `_NON_PERSONAL` out-of-scope set.

## 3. Component 2B — Script canonicalization

### 3.1 Canonical map

Use `scripts/validate_contribution.py::LANG_SCRIPT` as the single source of truth for language→ISO-15924
(extend it if any of the 60 languages is missing). Every script value must be derived as
`script = LANG_SCRIPT[language]` — language-driven, so ambiguous values like `CJK` resolve correctly
(zh→`Hans`, ja→`Jpan`, ko→`Kore`).

### 3.2 Generator fix

`scripts/generate_records.py` (and `scripts/migrate_v1_to_v2.py`) `SCRIPT_MAP` — make it complete for all 60
languages (add `ta`/`te`/`my` + any other gaps) and source it from the same canonical map, so future
generation never mislabels.

### 3.3 Corpus migration

A deterministic migration (a new `scripts/canonicalize_scripts.py`) that rewrites every record's `script`
to `LANG_SCRIPT[language]` on the **canonical main jsonl** (`data/pii_anon.jsonl.gz`), run **before**
`generate_subsets.py` so the re-derived splits/subsets inherit the canonical scripts (no separate
split/subset migration needed). Fixes the genuine `Latn` mislabels AND collapses the human-readable
duplicates in one pass. Streaming, count-checked, atomic (mirrors `scripts/v2_0_0_to_v2_1_0.py`). (If run
standalone outside the build, it must also cover the already-derived splits/subsets.)

### 3.4 Headline + analysis

Recompute the true distinct-script count post-canonicalization; correct the "32 writing systems" headline in
README/DATASHEET to that number. Refresh `results/tier-a/multilingual_by_script.md` (now consistent) at the
2A re-score step.

`pii-anon baselines --detectors regex,scrubadub,spacy,stanza,flair,gliner,piiranha,presidio --split test --languages en --out results/baselines/v22dev-local-en/`.

budget-gated → Phase 3). Do NOT overwrite the v2.0.0 `tier1-en-all` headline; write to a new results dir.

## 5. Generation/build sequence (ordered)

1. **2A.1–2A.4** taxonomy + crosswalk + schema + emitters + ETHNICITY (code/config; foundation).
2. **2B.2** generator `SCRIPT_MAP` fix (so new records are born correct).
3. **2A.5** set lattice targets + rebuild `eval_lattice.json`.
4. **2A.5** `generate_lattice_fill.py` → new Art-9 + non-personal records.
5. **2A.6** merge → enrich chain → honesty re-apply (`scripts/v2_0_0_to_v2_1_0.py` on the main) → `validate`.
6. **2B.3** canonicalize `script` on the **main canonical jsonl** (before subset regen).
7. **2A.6** `generate_subsets.py` — re-derives all splits/subsets from the canonicalized, honest main, so new
   records + canonical scripts + honesty fields flow into every split/subset.
8. **2A.7 / 3.4** tests + docs updates.
9. **§4** local re-score → refresh per-type/coverage/by-script analyses.
10. Final gate run.

## 7. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Removing schema cruft breaks a record that uses it | Full-corpus scan first; BLOCK + report if any of the 23 are used (then add to taxonomy instead of removing). |
| Art-9 English-anchored values are unrealistic in non-English carriers | Disclose (AX-001 synthetic; per-language Art-9 localization is 2D). Power comes from count, not realism claims. |
| Lattice rebuild changes existing committed-cell targets / re-triggers large fill | `build_committed_lattice` is deterministic; diff `eval_lattice.json` before/after; the fill only closes deficits (new cells), existing cells already met. |
| Re-scoring local detectors is slow (GLiNER/Flair) | Deterministic; run in background; it's local-only (no budget). Write to a separate results dir (don't disturb the v2.0.0 headline). |
| Script canonicalization changes the "32 writing systems" headline | Recompute + correct the headline honestly; it's a data-quality fix, disclosed in CHANGELOG. |
| New records change split denominators → analyses shift | Expected; the 2A re-score refreshes the affected analyses; headline leaderboard waits for the consistent v2.2.0 cut. |
| Honesty fields must ride the new records | Re-apply `apply_honesty` in the build chain (step 2A.6) so new records carry the v2.1.0 honesty layer. |
